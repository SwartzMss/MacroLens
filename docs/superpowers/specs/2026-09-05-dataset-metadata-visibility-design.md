# 数据集元数据可见性设计

## 背景

MacroLens 的指标数据同时包含面向用户的透明度信息和面向工程的审计信息。两类信息的用途不同：前者帮助用户理解数据，后者服务于数据更新、调试和可复现性。

Issue #81 要求先确定 V1 的信息架构，不在本次工作中实现 UI。

## 决策

采用“概览简洁、详情透明、工程信息内部保留”的两层用户信息架构：

1. 指标卡片只承担快速扫描：最新值、最新期间和近期变化。
2. 指标详情页承担解释和核验：定义、统计频率、比较方法、来源、更新时间和覆盖期间。
3. 规则版本、解析器/runtime、工作流标识、内部校验指纹以及静态生成/runtime 实现细节不展示给普通用户。

近期变化必须按指标自身的可比基准计算，并在详情页明确说明基准；不能把“上一条观测”当作所有指标通用的解释。

## 本次交付

- 记录当前 UI 与目标政策之间的差距，避免把本次文档 PR 误解为已完成 UI 对齐。

## 验收标准

- 政策明确列出指标卡片、指标详情页和内部工程元数据的可见性边界。
- 政策明确区分更新时间、来源发布时间和数据覆盖期间。
- 政策定义近期变化的可比基准，并给出 GDP、CPI 等指标专属解释示例。
- 政策包含当前实现差距和后续 UI 对齐的非目标说明。
- 现有测试和静态检查继续通过。
