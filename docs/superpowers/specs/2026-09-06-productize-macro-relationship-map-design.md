# 宏观关系地图产品化设计

## 目标

让 #91 建立的解释性关系浏览器成为 MacroLens 的可发现产品能力：用户可以从主导航和首页进入 `/graph`，并在概念页直接看到与当前概念相关的关系类型、时间关系和解释。

## 范围与约束

- 复用现有 `data/relations/macro.json`、`graphRegistry`、`RelationshipCards` 和 `/graph`，不新增关系数据集或关系推断逻辑。
- 在 `BaseLayout` 的主导航加入“宏观关系”入口，指向 `/graph`。
- 在首页增加单独的关系地图入口卡，说明其用途并链接 `/graph`；保留现有精选学习路径和传导路径。
- 概念页继续根据 frontmatter 的 `graph` 字段读取关系，使用现有概念集合将存在的节点链接到 `/concepts/[id]`。
- 解释性关系默认显示简明摘要、关系类型、时间关系和解释；传统关系只显示现有轻量卡片，不补造 `lag` 或解释。
- 保持关系方向和对称关系规则不变：关系展示必须依据 `getConceptRelations` 的 `incoming`、`outgoing`、`symmetric` 结果。
- 主界面使用正常中文，不暴露 `metadata`、内部 schema 或“定量因果推断”等实现词汇。

## 组件与数据流

1. `BaseLayout.astro` 提供全站主导航入口。
2. `src/pages/index.astro` 提供首页关系地图卡，静态链接到现有 `/graph`。
3. `src/pages/concepts/[id].astro` 继续传入当前概念的关系和完整概念集合。
4. `RelationshipCards.astro` 根据关系是否包含解释性字段选择两种展示：解释性关系为可读且默认展开的关系详情，旧关系为当前的简洁关系卡。两者共享方向、节点链接与关系分组逻辑。
5. `/graph` 不改变其静态生成和节点切换行为，继续复用同一套关系数据和卡片组件。

## 用户体验

- 主导航使用“宏观关系”这一明确入口名称；它与“概念”“主题”“搜索”处于同一导航层级。
- 首页关系地图入口使用“看懂指标之间的关系”作为产品标题，说明用户可以阅读“谁影响谁、领先或滞后多久、为什么相关”，并用“打开宏观关系地图”作为行动入口。
- 概念页关系区保留现有“它与其他概念如何关联”标题。解释性卡片在页面首次加载时直接展示关系类型、时间关系和一段解释，避免用户必须先发现并展开卡片。
- 关系节点存在对应概念页时提供可点击链接；抽象图谱节点继续标记为“图谱概念”，不生成不存在的页面。
- 移动端保持单列布局，长标签和解释允许换行；导航入口仍可访问。

## 错误处理与兼容性

- 不修改关系数据解析、校验和方向算法；现有缺失节点、未知图谱和非法关系仍由 `graphRegistry` 抛出错误。
- 不改变没有解释性字段的关系输出，也不为旧关系推导时间关系或解释文本。
- 首页和导航只增加静态链接，不引入客户端状态或额外运行时依赖。

## 测试与验收
