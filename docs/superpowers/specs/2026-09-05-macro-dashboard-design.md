# Macro Dashboard Design

## Goal

把现有静态指标数据转化为首页上的宏观经济概览，让用户在不逐个打开概念页的情况下看到最新指标、数据变化、更新时间、官方来源和进一步阅读入口。

## Scope

本次只覆盖当前仓库已有并已注册的指标数据：GDP、制造业 PMI、M0、M1、M2、规模以上工业增加值、社会消费品零售总额、固定资产投资。CPI、核心 CPI 和 PPI 只有在对应数据集加入注册表后才会自动具备接入条件，本次不新增或臆造数据。

现有首页的学习路径和关系传导内容继续保留；现有概念索引、概念详情页、数据采集和运行时网络行为不改变。

## Architecture

指标 JSON 仍是唯一数据源。新增一个纯 TypeScript 的 dashboard 数据适配层，集中声明展示顺序、概念页链接和卡片需要的派生字段：最新观测值、上一观测值、绝对变化、最新数据期及来源元数据。该适配层只读取 `indicatorRegistry`，不发起网络请求，也不复制原始数据。

首页在 Astro 构建阶段调用适配层，把结果传给展示组件。展示组件负责指标卡片和近期变化区块的语义 HTML；样式放入独立 dashboard CSS，并沿用现有颜色、字体、卡片和响应式断点。每张卡片链接到同 ID 的概念详情页，来源标题链接到原始官方来源。

## Dashboard content

- 顶部概览：标题、说明和“数据来自现有官方数据集”的口径提示。
- 指标卡片：指标名称、最新值、数据期、相对上一期的变化、更新日期、来源和“查看定义/图表”链接。
- 近期变化：按声明的展示顺序列出最新值相对上一观测值的变化；只有至少两个观测值的指标才计算变化。
- 响应式布局：桌面端多列卡片，窄屏单列；长指标名称、负值和合并期间文本不能破坏布局。

数值格式依据数据单位：百分比显示 `%`，PMI 以指数值显示并保留一位小数；变化值带正负号，零显示为 `0.0`。日期和来源文本使用 JSON 中已有值，不在页面层重新推断发布日。

## Error handling and compatibility

- 注册表缺少 dashboard 声明的 ID 时，构建阶段抛出带 ID 的错误，避免生成不完整首页。
- 只有一个观测值时不显示误导性的变化值。
- 空的来源列表不导致页面崩溃，来源区显示“来源信息待补充”；当前数据集均有来源。
- 不改变现有概念详情页所使用的 `getIndicatorData` 接口和数据 JSON schema。

## Testing

- 为 dashboard 适配层添加测试，验证完整展示清单、最新/上一期值、变化方向、元数据透传和单点数据边界。
- 添加首页结构测试，验证所有现有指标卡片、更新时间、来源链接和概念页链接存在，并确认现有学习路径仍在首页。
- 执行项目既有 Node 测试、`npm run check` 和 `npm run build`，确认静态生成、类型检查和 Pagefind 构建均通过。

## Non-goals

- 不新增运行时 API、客户端数据请求或自动刷新机制。
- 不重构已有指标 JSON，也不补充当前不存在的 CPI/Core CPI/PPI 数据。
- 不改变现有概念页的展示逻辑或指标图表行为。
