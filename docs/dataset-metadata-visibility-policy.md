# 数据集元数据可见性政策

状态：V1 提案，关联 [Issue #81](https://github.com/SwartzMss/MacroLens/issues/81)

## 1. 目的与范围

本政策定义 MacroLens 在面向普通用户的页面中展示哪些数据集元数据，以及哪些信息只服务于数据工程、调试和可复现性。

政策适用于指标概览卡片、指标详情页和宏观快照相关界面。它不规定数据抓取、校验、静态构建或运行时实现方式。

核心判断标准是：信息是否帮助用户回答“这是什么、来自哪里、覆盖什么时间、多久更新一次，以及这个变化应该怎样理解”。如果信息只回答“系统是怎样实现的”，则保留在工程内部。

## 2. 信息层级

### 2.1 可见性矩阵

| 信息 | 指标卡片 | 指标详情页 | 工程内部 | 展示要求 |
| --- | --- | --- | --- | --- |
| 最新值 | 展示 | 展示 | 保留原始值 | 使用指标自身单位和精度 |
| 最新期间 | 展示 | 展示 | 保留原始期间值 | 直接标出月度、季度或其他统计期间 |
| 近期变化 | 展示简版 | 展示并解释 | 保留计算输入 | 必须使用指标定义的可比基准和单位 |
| 指标定义 | 不展示长文 | 展示 | 可保留内部版本 | 使用指标专属定义，不使用泛化描述 |
| 统计频率 | 不展示或仅以期间标签体现 | 展示 | 可保留校验规则 | 说明月度、季度等频率及其含义 |
| 比较方法 | 不放入卡片长文 | 展示 | 可保留计算实现 | 说明同比、环比、环比年化或其他基准 |
| 数据来源 | 不作为卡片主要信息 | 展示 | 保留完整来源记录 | 支持链接到官方来源；多个来源按数据用途区分 |
| 数据集更新时间 | 不作为卡片主要信息 | 展示 | 保留更新时间字段 | 说明这是数据集最近一次更新，不等于来源发布时间 |
| 数据覆盖期间 | 不展示长文 | 展示 | 保留原始覆盖记录 | 说明当前数据实际覆盖的起止期间 |
| 规则版本 | 不展示 | 不展示 | 展示/记录 | 仅用于工程审计、调试和复现 |
| 解析器或 runtime 信息 | 不展示 | 不展示 | 展示/记录 | 不属于指标解释 |
| 工作流标识 | 不展示 | 不展示 | 展示/记录 | 不属于用户理解数据所需信息 |
| 内部校验指纹 | 不展示 | 不展示 | 展示/记录 | 不暴露实现细节 |
| 静态生成或运行时请求实现 | 不展示 | 不展示 | 展示/记录 | 不构建开发者/debug 面板 |

### 2.2 指标卡片

卡片用于快速扫描，只保留：

- 最新值；
- 最新数据期；
- 近期变化。

卡片不承担完整的方法论、来源核验或工程状态说明。来源、更新时间和覆盖期间应在详情页提供，避免卡片把用户注意力从指标本身带向审计信息。

### 2.3 指标详情页

详情页必须提供理解和核验指标所需的上下文：

- 指标定义：说明测量对象、范围和单位；
- 统计频率：说明数据是月度、季度或其他频率；
- 比较方法：说明近期变化使用的基准及其统计含义；
- 数据来源：列出官方数据来源和必要的来源链接；
- 最后更新时间：说明数据集最近更新的日期；
- 覆盖期间：说明数据实际覆盖的起止期间。

定义、频率和比较方法必须针对当前指标编写。不能用“每个指标遵循自己的数据约定”或“与上一观测期间比较”替代真正的解释。

## 3. 近期变化的语义

“近期变化”表示：

> 最新观测值 − 该指标方法论定义的可比上一观测值。

这里的“可比”由指标自身的统计定义决定，而不是由所有数据集共享的数组位置或统一的“上一期”概念决定。展示时必须同时明确数值单位和比较基准；如果上一观测不存在，不得虚构变化值。

示例：

- GDP：`2026 年第 2 季度：-0.7 个百分点`。详情解释：“GDP 为季度指标，变化与上一季度比较。”
- CPI：详情必须明确展示的是环比、同比，还是其他价格比较口径。例如“2026 年 7 月 CPI 同比：+0.3%”，不能只写“较上一期 +0.3”。
- PMI：变化应说明指数点数变化，并与 50 的扩张/收缩临界点解释分开，不能把指数点数当作增长率。

如果卡片空间有限，卡片可以只显示简短的变化值；详情页必须补足完整的指标专属解释。

## 4. 时间与来源字段的区别

用户界面应区分以下概念：

- 数据来源：数据由哪个机构或官方数据集提供；
- 来源发布时间：某份来源材料何时发布；
- 数据集更新时间：MacroLens 当前数据集何时完成最近一次更新；
- 覆盖期间：数据值实际对应的时间范围。

这些日期不能互相替代。例如，来源材料在 2026-09-05 发布，不代表每个观测值都对应 2026-09-05；数据集更新时间也不等于最新数据期。详情页应让用户能够分别理解“数据何时发布”“数据测量何时”和“MacroLens 何时更新了这份数据”。

## 5. 工程元数据边界

以下信息默认只保留在数据文件、测试、构建日志或其他工程记录中：

- 规则版本，例如宏观快照规则的版本号；
- 解析器、runtime 和静态生成实现细节；
- 数据更新工作流名称或运行标识；
- 内部验证指纹、方法学 fingerprint 和完整性审计标记；
- 任何用于排查实现问题、但不能帮助用户解释指标的内部字段。

如果某个工程字段同时包含用户真正需要的内容，应拆分为用户可理解的字段。例如，保留“CPI 采用官方发布的同比值”作为比较方法说明，但不展示用于校验该方法的内部 fingerprint。

## 6. 当前实现差距与本次非目标

当前代码中仍有一些实现信息位于用户界面：

- 宏观快照显示“规则版本”；
- 首页显示“静态生成 · 无运行时数据请求”；
- 指标卡片直接显示来源和更新时间；
- 部分变化标签仍使用泛化的“较上一期”。

这些现状用于说明政策落地时需要处理的差距，不代表本 PR 修改了 UI。本 PR 只确定可见性政策，不实现字段移动、文案替换、比较逻辑调整或页面重构。

后续 UI 实现应以本政策为验收依据，至少完成：

1. 从普通用户界面移除工程元数据；
2. 将来源、更新时间和覆盖期间放到详情页的透明度信息区域；
3. 为每个指标补充定义、频率和比较方法；
4. 把近期变化改为指标专属且单位明确的表达；
5. 保持指标卡片的扫描效率，不把完整方法论塞入卡片。

## 7. 非目标

V1 不包含：

- 开发者或数据工程 debug dashboard；
- 公开规则版本、解析器/runtime、工作流或校验指纹；
- 为所有指标强行套用同一种比较基准；
- 在没有确定最终信息架构前直接改 UI；
- 改变数据抓取、校验、生成或部署流程。
